### latest 태그를 쓰면 안 되는 이유

수업을 들을 때 이 부분이 가장 어려웠다. "latest = 최신 버전"이라고 생각하고 있어서, 최신을 받는게 왜 문제인지 몰랐다.

정리하면서 알게 된 건 **latest가 "최신"을 보장하는 태그가 아니라, 태그를 안 적었을 때 자동으로 붙는 이름** 이라는 점이다. 누군가 새 이미지를 latest로 push하면 같은 이름이 가리키는 내용이 바뀐다. 그래서 서버 두 대가 다른 날 latest를 받으면 **이름은 같은데 서로 다른 코드가 돌 수 있다.** 장애가 나면 어떤 버전인지 추적할 수 없고, 되돌릴 버전도 불분명해진다.

**latest 대신 버전 태그를 무조건 지정해야 한다.**

### CMD와 ENTRYPOINT
둘 다 컨테이너가 시작할 때 실행되니 같은 기능으로 보였따. 차이는 **`docker run` 뒤에 인자를 줬을 때**만 드러난다. CMD는 통째로 바뀌고, ENTRYPOINT는 그대로 실행되면서 인자가 뒤에 붙는다. 둘을 함께 쓰면 ENTRYPOINT가 고정 명령, CMD가 기본 인자가 된다는 조합까지 알고 나서 정리가 됐다.

### 레이어에서 rm을 해도 용량이 안 줄어드는 이유
`RUN rm -rf ...`를 따로 적으면 파일이 지워질 거라고 생각했다. 그런데 레이어는 쌓이기만 하고 아래 레이어는 바뀌지 않기 때문에, 위에서 지워도 **가려질 뿐 아래 레이어에 그대로 남는다.** 그래서 설치와 정리를 한 RUN 안에서 `&&`로 묶어야 한다.

<br>

- **`nginx`만 써도 `docker.io/library/nginx:latest`로 해석된다.** 레지스트리와 계정이 생략되어 있었던 것이다. push할 때 이미지 이름에 레지스트리 주소를 붙이는 이유도 여기서 이해했다.
- **`EXPOSE`는 포트를 열지 않는다.** 문서용 표시일 뿐이고 실제 연결은 `-p`가 한다.
- **shell 형식으로 CMD를 쓰면 `docker stop` 신호가 앱에서 안 간다.** 셸이 PID 1이 되기 때문이다. 
- **ARG로 비밀번호를 넘기면 `docker history`에 남을 수 있다.** 비밀 값은 실행 지점에 주입해야 한다.
- **시맨틱 버저닝에서 1.9 다음 MINOR는 1.10이다.** 각 자리가 독립된 정수라는 걸 처음 의식했다.
- **Python 이미지는 alpine보다 slim을 고르는 경우가 많다.** alipine의 musl libc 때문에 C 확장 라이브러리가 꼬일 수 있어서다. "무조건 alpine이 좋다"가 아니라 언어와 라이브러리에 맞춰 골라야 한다.

<br>

이미지는 **지울 수 없는 레이어가 쌓인 것**이고 캐시는 **한 번 깨지면 아래가 다 다시 돈다**는 두 가지를 기억하고 나니, Dockerfile 명령 순서를 왜 그렇게 생성했는지 이해됐따. latest는 "최신"이 아니라 "이름표"라는 것도 이번에 정리했다.
