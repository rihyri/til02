## 오늘 배운 것
- 서버와 컨테이너가 많아지면 배치, 개수 유지, 교체를 자동으로 맡아 줄 컨테이너 오케스트레이션이 필요하다는 것을 배웠다.
- Kubernetes는 원하는 상태를 YAML로 선언하면 그 상태를 계속 유지해 주는 **선언형** 방식이라는 것을 배웠다.
- 컨트롤 플레인(apiserver, etcd, scheduler, controller-manager)과 노드(kubelet, kube-proxy, 컨테이너 런타임)의 역할을 정리했다.
- `kubectl apply` 한 번에 API 서버 → etcd → 컨트롤러 → 스케줄러 → kubelet 순서로 일이 이어지는 흐름을 배웠다.
- etcd 과반수 원리 때문에 컨트롤 플레인을 3대, 5대처럼 홀수로 두고, 앞에 HAProxy + Keepalived로 VIP를 둔다는 것을 배웠다.
- Minikube로 로컬 클러스터를 만들고, kubectl 명령 구조와 상태 확인 명령을 익혔다.

## 헷갈렸던 점

### Node와 Pod가 정확히 뭔지

수업 내내 Node와 Pod라는 단어가 나왔는데 둘의 경계가 잘 안잡혔다. 정리하고 나니 **Node는 "컴퓨터", Pod는 "그 컴퓨터 위에서 도는 실행 단위"** 였다. Docker 때 기준으로 보면 Docker가 설치된 서버가 Node, 그 위에 띄운 컨테이너를 한번 감싼 것이 Pod다.

특히 "왜 컨테이너가 아니라 Pod라는 단위가 따로 있나"가 궁금했는데, Pod 안의 컨테이너들은 **IP와 스토리지를 공유**해서 `localhost`로 통신할 수 있고, kubernetes는 이 묶음을 한 노드에 통째로 배치한다. 그래서 스케줄러가 관리의 최소 단위가 컨테이너가 아니라 Pod가 된다.

### "노드는 물리 PC에 종속되지 않는다."

처음에는 "PC가 꺼져도 노드는 안 꺼진다"는 뜻으로 받아들였는데, 다시 정리해보니 그건 아니었다. 노드는 물리 서버일수도, VM일 수도 있어서 **PC 한 대에 노드가 여러 개 있을 수 있다**는 뜻이지, 노드가 올라간 머신이 꺼지면 그 노드는 당연히 `NotReady`가 된다. 대신 Deployment로 관리되던 Pod는 다른 노드에 새로 뜨기 때문에 **서비스는 이어질 수 있다**는 것이 핵심이었다.

같은 맥락에서 "Kubernetes는 최소 2대가 필요하다"도 운영 환경 권장 구성에 가까운 말이었다. Minikube처럼 노드 하나가 컨트롤 플레인과 워커를 함께 맡는 단일 노드 클러스터도 가능하다.

### 스케줄러가 Pod를 띄우는 줄 알았다.
이름만 보고 스케줄러가 Pod를 실행까지 하는 줄 알았는데, 스케줄러는 **어느 노드에 둘지 API 서버에 적기만** 한다. 실제 실행은 그 노드의 kubelet이 API 서버를 지켜보다가 자기 노드에 배정된 Pod를 발견한다. 구성 요소끼리 직접 명령하지 않고 **API 서버라는 게시판을 통해서만** 일을 주고받는다는 구조를 이해하니 나머지 흐름도 자연스럽게 이어졌다.

<br>

### 새롭게 알게 된 것

- **etcd와 직접 통신하는 것은 API 서버뿐이다.** 다른 구성 요소는 모두 API 서버를 거친다.
- **etcd를 4대로 늘려도 3대와 버틸 수 있는 장애 수(1대)가 같다.** 짝수 증설은 비용만 늘어난다.
- **etcd가 과반을 잃어도 이미 돌고 있는 Pod는 멈추지 않는다.** 새 배포나 변경만 막힌다.
- **kubelet은 Pod가 아니라 노드의 일반 프로세스**라서 `kubectl get pods -n kube-system`에 안 보인다. 반대로 kube-proxy는 보통 DaemonSet Pod로 떠서 목록에 보인다.
- **kube-proxy는 규칙을 커널에 깔아 두는 역할**이라 잠깐 멈춰도 기존 통신은 계속된다.
- **컨트롤 플레인 노드에는 taint가 걸려 있어** 일반 Pod가 배치되지 않는다.
- `--dry-run=client -o yaml`로 YAML 초안을 뽑을 수 있어서, 매니페스트를 처음부터 손으로 쓰지 않아도 된다.

<br>

**Node는 컴퓨터, Pod는 그 위에서 도는 최소 실행 단위**이고 모든 구성 요소가 **API 서버를 중심으로 원하는 상태를 맞춰 간다**는 그림을 잡고 나니, 스케줄러가 노드를 정하기만 하는 이유와 etcd를 홀수로 두는 이유까지 한 흐름으로 이해됐다.
