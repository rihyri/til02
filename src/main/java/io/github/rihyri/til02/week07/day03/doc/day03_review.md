# Week 07 - Day 03. 회고

<br>

이번 수업에서는 Spring의 트랜잭션 전파 옵션인 `REQUIRED`, `REQUIRES_NEW`, `NESTED`, `SUPPORTS` 를 학습했다. 수업에서는 주문 접수와 처리, 작업 큐, 비동기 메서드가 연이어 호출되는 예제를 살펴보았다. 처음에는 어노테이션만 보고 트랜잭션이 어떻게 분리되는지 이해하기 어려웠다.

<br>

- **REQUIRED** : 주문 접수와 실제 주문 처리가 하나의 트랜잭션이면, 뒤쪽에서 예외가 발생했을 때 앞서 저장한 작업 큐까지 함께 롤백된다. 
- **REQUIRES_NEW** : 주문 트랜잭션과 감사 로그 트랜잭션을 분리하면, 부모 주문 작업이 실패해도 이미 커밋된 로그는 유지된다. 
- **NESTED** : SAVEPOINT를 이용하면 주문 처리 부분만 취소하고, 부모가 생성한 작업 큐는 남길 수 있다. 단, 부모가 롤백하면 자식 작업도 사라진다. 
- **SUPPORTS** : 사용자 조회처럼 트랜잭션이 반드시 필요하지 않은 메서드는 호출 환경에 따라 트랜잭션에 참여하거나 트랜잭션 없이 실행할 수 있다.

<br>

이번에 가장 어려웠던 부분은 `NESTED`와 `REQUIRES_NEW`의 차이였다. 둘 다 자식 작업을 따로 롤백할 수 있다는 점은 비슷했지만, `REQUIRES_NEW`는 별도 물리 트랜잭션이고 `NESTED`는 부모 트랜잭션의 내부 SAVEPOINT를 사용한다는 점이 다르다. 또한 `@Async`가 붙으면 볼드의 스레드에서 실행되므로 부모 트랜잭션을 그대로 이어받지 않는다는 것도 알게 되었다.

<br>

트랜잭션 전파 옵션이 여러가지인 것도 알게 되었고, 어떠한 상황에서 어떻게 적절한 전파 옵션을 사용해야 할지 여러 상황들을 통해 감을 잡아야 할 것 같다.
