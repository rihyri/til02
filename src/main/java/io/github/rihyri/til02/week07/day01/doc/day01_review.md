# Week 07 - Day 01. 회고 

<br>

이번 수업에서는 MySQL에서 조회 성능을 높이는 핵심 도구인 **인덱스**를 학습했다. 인덱스가 단순히 검색을 빠르게 만드는 기능을 넘어, B-Tree 계열 구조를 통해 데이터를 탐색하고 정렬된 상태로 관리한다는 점을 이해했다.

기본 키, 고유 인덱스, 일반 인덱스의 차이를 살펴보고, 특히 **복합 인덱스에서는 컬럼을 어떤 순서로 배치하느냐가 중요하다**는 점이 기억에 남았다. 단순히 조건절에 사용되는 컬럼마다 인덱스를 만들기보다는 실제 조회 패턴을 먼저 확인해야 한다는 사시롣 알게 되었다.

<br>

인덱스가 있으면 언제나 빠를 것이라고 생각하기 쉽지만, INSERT가 UPDATE 등 쓰기 작어벵서는 오히려 추가 비용이 생길 수 있다는 부분이 흥미로웠다. 또 `WHERE`, `JOIN`, `ORDER BY`에 인덱스를 적용하더라도 MySQL 옵티마이저가 반드시 사용하지는 않으며, 상황에 따라 전체 테이블 스캔을 선택할 수 있다는 점도 새로웠다.

<br>

복합 인덱스에서 선행 컬럼이 중요한 이유를 이해하긴 했지만, 범위 조건과 정렬까지 함께 사용했을 때 어느 부분까지 인덱스를 활용하는지는 더 익숙해져야 할 것 같다. 

앞으로는 쿼리가 느리다고 해서 곧바로 인덱스를 추가하기보다, **자주 실행되는 SQL 실행 → EXPLAIN 분석 → 인덱스 설계 → 다시 측정**하는 순서로 접근하여 살펴봐야겠다.

인덱스는 많이 만드는게 좋은 것이 아니라, 실제 쿼리가 필요로 하는 위치에 알맞게 적용할 수 있도록 공부해야겠다.
