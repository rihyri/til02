# Week 07 - Day 04. 회고

<br>

이번 수업에서는 트랜잭션의 기본 롤백 규칙을 복습하고, 외부 API 호출이 포함된 서비스에 Retry와 타임아웃을 적용하는 방법을 학습했다. 특히 외부 상품 API에서 데이터를 가져와 MySQL에 저장하는 과정을 따라가며, FeignClient, 응답 DTO, 서비스, Repository가 어떻게 연결되는지 확인했다.

<br>

`@Transactional`이 붙어 있다고 해서 모든 오류가 자동 롤백되는 것은 아니라는 점이 중요했다. 언체크 예외는 기본적으로 롤백되지만 체크 예외는 설정이 필요하고, 예외를 내부에서 잡고 정상 종료하면 롤백이 일어나지 않을 수 있다.

또한 `@Retryable`은 실패한 메서드를 다시 실행하는 반면, `Retryer.NEVER_RETRY`는 Feign 자체의 재시도를 끄는 설정이라는 차이를 이해했다. 외부 API의 일부러 만들어 둔 랜덤 오류를 통해 이 차이를 직접 관찰할 수 있었다.

<br>

외부 상품을 조회한 뒤 메인 DB에 저장할 때는 JSON 응답의 `message.contents`를 꺼내 각 엔티티로 변환한다. 전체 상품을 저장할 때는 마지막 페이지까지 반복해야 하며, 요청 인덱스가 0부터 시작한다.

<br>

외부 API 호출이 실패했다고 해서 두 시스템의 DB가 동시에 롤백되는 것은 안다. 또 전체 저장 메서드를 재시도하면 이전 페이지 처리도 반복될 수 있으므로, 실제로 서비스 하기 위해선 중복 저장 방지와 예외 메시지 구분이 필요할 것 같다.
