# Week 09 - Day 02. 회고

<br>

## 오늘 배운 것
- 모놀리틱 쇼핑몰을 user / product / order 세 서비스로 나눌 때 엔티티 참조, 존재 확인,주문 상태가 어떻게 바뀌는 지 배웠다.
- 새 서비스가 Kafka 토픽을 발행하고 구독하며 Choreography Saga를 이루는 구조를 봤다.
- Kafka 설정 항목(acks, enable.idempotence, group-id, auto-offset-reset)의 의미를 정리했다.
- DDD의 기본 용어(도메인, 서브 도메인, 모델, 유비쿼터스 언어)와 서브도메인 세 종류를 배웠다.
- 전략적 설계(바운디드 컨텍스트, 컨텍스트 맵)와 전술적 설계(엔티티, VO, 애그리거트, 리포지터리, 도메인 서비스, 도메인 이벤트)를 배웠다.
- DDD 4계층 아키텍처와 의존성 역전(포트와 어댑터)을 배웠다.

<br>

### 비슷한 용어
- **도메인 서비스 vs 응용 서비스** : 둘 다 "서비스"라서 처음에는 차이를 몰랐다. **규정집(규칙 계산)과 담당자(흐름 조율)** 로 나눠 생각하니 구분이 됐다. 배송비 기준은 규정이므로 도메인 서비스, 주문을 만들고 저장하는 흐름은 담당자이므로 응용 서비스이다.
- **포트 vs 어댑터 :** 콘센트 구멍(인터페이스)과 플러그(구현체)로 생각하니 이해가 됐다. 구멍 모양은 안쪽(도메인, 응용)이 정하고 바깥(인프라)이 거기에 맞춰 플러그를 만든다.
- **애그리거트 :** 엔티티와 무엇이 다른지 헷갈렸다. 애그리거트는 객체 하나가 아니라 **"항상 함께 규칙을 지켜야 하는 묶음"** 이고, 루트 엔티티가 그 묶음의 문지기라는 점을 알고 나서야 정리가 됐다.

<br>

### 새롭게 알게 된 것

- **MSA로 쪼갤 때 "객체 대신 ID"가 되는 것은 DDD 애그리거트 규칙과 같은 이야기다.** 모놀리틱 안에서도 애그리거트끼리 ID로 참조해 두면 나중에 서비스로 떼어내기 쉽다.
- **`auto-off-set-reset=liest`는 Saga 안정성과 연결된다.** 기본값 latest로 두면 서비스가 처음 뜨기 전에 쌓인 이벤트를 건너뛰어서 주문이 PENDING에 계속 머물 수 있다.
- **같은 단어도 컨텍스트마다 다른 모델이어야 한다.** "상품" 하나를 전시, 재고, 배송이 같이 쓰면 한 쪽 수정이 다른 쪽을 깨뜨린다.
- **VO를 기본으로 쓰고, 추적이 필요할 때만 엔티티로 올린다.** 권장사항인데, 지금까지는 거의 모든 것을 엔티티(테이블 한 줄)로만 생각해 왔다.
- **`@TransactionalEventListener`는 트랜잭션이 없으면 아예 호출되지 않는다.** 기본값이 AFTER_COMMIT이라는 것과 함께 Spring 공식 문서에서 확인했다.
- **도메인은 저장 기술을 몰라야 한다.** 리조피토리 인터페이스를 도메인에 두고 구현을 인프라에 두면 JPA를 MyBatis로 바꿔도 도메인 코드는 그대로다.

<br>

이번 수업을 다시 정리해보니 DDD는 완전히 새로운 내용이 아니라 **1일차에 배운 "어디서 자르고, ID로 참조하고, 사실을 이벤트로 알린다"를 설계 원칙으로 정리한 것**이었다.

아직 헷갈리는 부분이 많은데 실제 패키지 구조와 내용을 생각하며 더 공부해야겠다.
